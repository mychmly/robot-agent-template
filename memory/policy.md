# policy.md

## 文档用途

本文件用于说明什么应该写入记忆、写到哪里、每轮运行后如何更新。

它是“记忆规则”，不是具体记忆内容。

## 1. 哪些信息应进入最近交流

- 最近一次巡视事件摘要：
- 最近一次系统回复摘要：
- 最近一次结构化决策摘要：
- 本轮是否主动提醒了主人：

## 2. 哪些信息可沉淀为长期记忆

- 可沉淀的长期偏好：主人喜欢怎样被提醒、能接受多高的提醒频率
- 可沉淀的稳定观点：主人更在意哪些公共区域的秩序
- 可沉淀的长期事实：哪些提醒模式更有效，哪些问题经常重复出现
- 只有明确属于长期、稳定、可复用的信息，才应进入长期记忆：

## 3. 哪些信息只保留在当前状态

- 当前轮巡视结果：
- 当前轮下一步动作：
- 当前是否存在待提醒事项：
- 当前会话最新运行态快照：

## 4. 哪些信息不应写入记忆

- 不应写入的内容 1：一次性、未确认的画面猜测
- 不应写入的内容 2：测试说明、报错文本或高风险结论的猜测性描述
- 不应写入的内容 3：时间 / 天气 / 常识检索这类纯运行态查询结果

## 4-1. `SOUL.md` 与记忆文件的分工

- `SOUL.md`：保存稳定人格、长期介入原则、提醒风格和边界意识
- `recent-interactions.md`：只保存 patrol 相关逐轮巡视事件摘要
- `long-term-memory.md`：保存稳定偏好、复发模式和可复用经验
- 前端 `Runtime Snapshot`：保存当前激活会话的最新运行态，不写入 Markdown 持久记忆

默认原则：

- 高频运行结果不再默认全部写入 `memory/`
- 只有 patrol 相关短期上下文，才允许进入 `recent-interactions.md`
- 只有足以改变长期人格或介入原则的稳定模式，才考虑更新 `SOUL.md`
- 若用户希望系统稳定记住个人偏好或背景信息，默认应使用“请记住：...”这类显式授权表达
- 当前模板默认关闭 `owner-profile.md` 的自动晋升；若后续要做更自动化版本，应把它作为显式开关能力，并先明确晋升阈值与人工复核策略

## 5. 每轮运行后的最小更新顺序

1. 若本轮属于 patrol 场景，更新 `recent-interactions.md`
2. 若本轮形成稳定、可复用信息，再更新 `long-term-memory.md`
3. 若用户使用“请记住：...”这类显式授权表达，再低频补充 `owner-profile.md`
4. `current-state.md` 与 `latest-response.md` 已退出当前模板高频持久化主链

## 6. 当前写法提醒

- `recent-interactions.md` 应按轮记录 patrol 摘要，不应把工具查询、寒暄或常识问答混入其中
- `long-term-memory.md` 只收稳定偏好与复发模式，不应把临时杂乱或单次提醒直接沉淀进去
- 非显式授权的个人偏好表达（如“我喜欢……”“我不希望……”）默认只做理解，不自动写入 `owner-profile.md` 或 `long-term-memory.md`
- 若后续要开放“重复候选自动晋升到 `owner-profile.md`”，必须先明确：触发阈值、适用类别、是否需要人工确认，以及该机制在课堂版中默认关闭
- `SOUL.md` 不应在每轮巡视后自动改写；若出现稳定模式，应先沉淀为候选变化，再低频修订
- 当前会话的“最近一次回复 / 最近一次状态”应在前端 `Runtime Snapshot` 中展示，而不是继续高频写回 Markdown
